# MedSpa Copilot V2.0 产品优化设计方案

> 版本：v1.0
> 日期：2026-07-02
> 状态：待评审
> 范围：产品优化方案（三角色功能完善）+ 官方网站设计（内部迭代规划）

---

## 0. 文档说明

本文档是 MedSpa Copilot V2.0 的完整产品优化设计方案，作为内部迭代规划，指导后续开发。

### 0.1 设计原则

1. **第一性原理**：从医美机构收入公式出发，聚焦四个核心环节的漏点修复
2. **三角色闭环**：超级管理员（平台生态）、机构管理员（运营管理）、咨询师（业务执行）三层协同
3. **AI 驱动**：每一项新增功能都以 AI 能力为核心差异，而非纯管理工具
4. **数据驱动迭代**：所有功能上线后需可量化验证效果

### 0.2 V1 现状评估

V1 完成度约 85%，核心流程（录音上传→ASR→标签生成→客户档案→每日工作台→话术生成）已跑通。主要缺口：

- 基建层：SQLite 需切 PostgreSQL、OSS/ASR 为 mock、合规检查未独立、组件硬编码色值
- 功能层：超级管理员完全缺失、机构管理员有 4 个模块但深度不足、咨询师缺少增长型功能
- 数据层：线索管理空白、客户生命周期缺失、绩效/营销/满意度均未覆盖

| 线索录入 | 手动录入：姓名、手机号、来源、意向项目、预算、备注 | P0 |
| 批量导入 | Excel 模板下载 + 批量导入；导入时去重（手机号） | P0 |
| 线索详情 | 基础信息 + 跟进记录 + 标签 + 关联咨询师 + 转化轨迹 | P0 |
| 线索评分 | AI 根据线索信息自动评分（A/B/C/D 类）：基于意向项目数、预算、来源质量等维度 | P1 |

#### 3.1.2 线索分配

| 功能 | 说明 | 优先级 |

| 手动调整 | 管理员可手动重新分配单条线索 | P0 |
| 批量分配 | 选中多条线索，批量分配给指定咨询师 | P0 |

#### 3.1.3 线索回收

| 功能 | 说明 | 优先级 |
|---|---|---|

#### 3.1.4 转化漏斗

| 功能 | 说明 | 优先级 |
|---|---|---|

| 转化分析 | 各来源的转化效果对比（哪个渠道来的线索质量最好）；各咨询师的线索转化率排名 | P1 |

**数据模型**：`Lead`、`LeadAssignmentRule`

**转化流程**：线索 → 咨询师跟进 → 约访 → 到店面谈 → 录音解析 → 创建正式客户（lead.status = converted，关联 customerId）

### 3.2 客户生命周期运营

**目标**：客户从首次接触到流失的完整旅程管理，提升复购和客户终身价值。

#### 3.2.1 生命周期阶段

```
线索 → 首访 → 面谈 → 成交 → 复购 → 沉睡 → 唤醒 → 流失
                                         ↑_______|
                                         (唤醒成功回到复购)
```

| 阶段 | 定义 |
|---|---|
| 线索 | 尚未到店，仅联系方式 |
| 首访 | 已到店首次面诊，尚未成交 |
| 面谈 | 有深入咨询，待决策 |
| 成交 | 首次付费完成 |
| 复购 | 二次及以上消费 |
| 沉睡 | 90 天（可配置）无互动无消费 |
| 流失 | 180 天（可配置）无互动无消费，且唤醒失败 |

#### 3.2.2 阶段流转

| 功能 | 说明 | 优先级 |
|---|---|---|
| 自动流转规则 | 配置每个阶段的进入条件：如"成交后自动进入复购期"、"90 天无互动自动进入沉睡期"；支持多条件组合 | P0 |
| 手动调整 | 管理员可手动调整客户阶段；调整写入审计日志 | P0 |
| 流转记录 | 每个客户的阶段变更历史：时间、原阶段、新阶段、变更原因（自动/手动） | P1 |

#### 3.2.3 生命周期看板

### 4.2 客户分层运营

**目标**：按客户价值自动分层，差异化配置资源和策略。

#### 4.2.1 分层模型

采用 RFM 模型扩展：

| 维度 | 说明 |
|---|---|
| R (Recency) | 最近一次互动/消费时间 |
| F (Frequency) | 互动频次 / 到店次数 |
| M (Monetary) | 累计消费金额 |

加上扩展维度：
- **I (Intent)**：意向度（基于标签分析）
- **P (Potential)**：复购潜力（基于标签 + 生命周期阶段）

综合计算得分为 A/B/C/D 四级：

| 层级 | 定义 | 运营策略 |
|---|---|---|
| A 类 | 高价值高意向 | 高频跟进 + 主管协同 + 专属优惠 + 优先资源 |
| B 类 | 中高价值 | 标准跟进节奏 + 升单推荐 |
| C 类 | 一般价值 | 批量 nurture + 自动化触达 |
| D 类 | 低价值低意向 | 低优先级 + 周期性唤醒 |

#### 4.2.2 分层功能

| 功能 | 说明 | 优先级 |
|---|---|---|
| 自动计算 | 每日凌晨自动重新计算所有客户层级和得分；人工手动调整（写入审计日志） | P0 |
| 分层看板 | 各层级客户数/占比饼图；各层级转化率/客单价/复购率对比表 | P0 |
| 层级流转 | 客户层级变化历史；最近升级/降级客户列表 | P1 |
| 分层筛选 | 客户列表可按层级筛选；配合其他筛选条件做精准营销 | P0 |
| 分层策略绑定 | 每个层级绑定不同的默认跟进策略（SOP 模板、跟进频率） | P1 |
| 层级预警 | 客户从 A 降到 B 等降级时自动预警，推送挽回建议 | P1 |

**数据模型**：
- `Customer` 扩展：`tier`（A/B/C/D）、`tierScore` Float、`rfmScore` JSON（各维度得分）

## 7. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
