# 医美 AI 智能管家开发计划

更新时间：2026-08-23

## 目标与边界

当前项目具备完整的产品叙事、部分真实接口和较强的演示界面，但工程状态仍接近可交互原型。后续开发目标不是继续扩展页面数量，而是把最短价值链做成可部署、可追责、可验证的 SaaS 闭环：

`录音上传 -> 异步解析 -> 可追溯客户标签 -> 跟进计划/任务 -> 合规话术 -> 任务执行记录`

本计划严格遵守 `AGENTS.md`：PostgreSQL、Redis/BullMQ、机构隔离、从 session 获取 orgId、AI 输出二次校验、话术合规审查以及审计日志。

## 实施顺序

### P0：生产基线与数据安全

目标：让系统具备正确的数据边界，消除当前最容易造成数据串租户和运行环境不一致的问题。

工作项：

1. 将 Prisma 数据源从 SQLite 切换为 PostgreSQL，并提供 Docker 本地依赖、迁移与种子数据的可重复启动路径。
   `prisma/schema.prisma` 是唯一的 Prisma CLI 入口；根目录历史 `schema.prisma` 暂不删除，避免影响已有本地环境。
2. 明确多租户访问层：所有业务查询必须经统一的 `orgId` 注入与资源归属校验；咨询师额外校验 `consultantId`。
3. 审核并修复客户、录音、任务、标签等核心 API 的查询条件组合错误，禁止客户端传入的 `orgId` 参与授权决策。
4. 将标签修改、客户转移、SOP 审核和任务关键状态变更的审计日志补齐到统一格式。
5. 增加 API 授权与跨机构访问的测试用例。

验收标准：

- 新环境执行迁移和种子数据后可启动应用与 Worker。
- 机构 A 的用户不能读取、修改、下载或订阅机构 B 的任意业务资源。
- 咨询师不能操作不属于自己的客户、录音与任务；机构管理员拥有机构范围权限。
- `pnpm lint` 与 `pnpm typecheck` 通过。

### P1：录音解析闭环（F1）

目标：录音上传后可靠地产出带证据的标签、策略和待办，且失败可以定位与重试。

工作项：

1. 移除 API 路由内同步执行 Worker 的降级路径；上传只负责校验、持久化和入队。
2. 完整定义 BullMQ Job 的幂等语义、重试次数、退避策略和失败状态，避免重复生成标签及任务。
3. 重构 `CustomerTag`：支持同一维度多值标签，保留来源录音、原句、偏移、置信度和人工修订状态；为替换/保留历史定义规则。
4. 接通 Worker 的 ASR -> 标签提取 -> 策略生成 -> FollowUpPlan/FollowUpTask 创建流程，使用事务保证阶段产物一致。
5. SSE 进度端点改为有明确事件类型与断线恢复标识的协议，并避免无界轮询压力。
6. 补齐 OSS 文件校验、大小/格式限制、失败清理与权限访问策略。
7. 实现腾讯云 ASR 适配器，固定使用录音文件识别 `16k_zh_en_2.0`：提交异步任务、接收/轮询结果、映射词级时间戳和说话人分离结果。
8. 建立医美热词表及版本机制，并用真实脱敏录音抽样对比通用引擎与热词配置后的项目名、药械名、医生名识别准确率。
9. 角色分离先仅针对取得单独授权的咨询师灰度启用；客户只使用自动说话人分组，不采集或持久化客户声纹。无法确认角色的片段必须保留为 `unknown`。

验收标准：

- 同一录音重复投递不会重复创建有效标签、计划或任务。
- 每一步状态可在前端观测，失败显示用户可理解的信息且保留开发诊断日志。
- 标签能显示证据原句；同维度多个需求/顾虑不会互相覆盖。
- 全部 ASR 和 LLM 长耗时步骤仅由 Worker 执行。
- 16k 单声道双人咨询录音可返回带时间戳的说话人分组；角色不确定时不会被错误标记为客户或咨询师。
- 录音 URL、ASR 密钥和完整转写不出现在应用日志；腾讯云密钥仅由服务端环境变量提供。

### P2：每日工作台与合规闭环（F3）

目标：咨询师每天可以明确知道该做什么、获得安全话术、记录结果并反馈后续策略。

工作项：

1. 按咨询师、当天和优先级稳定查询待办，明确时区、延期、跳过原因与已完成状态的业务规则。
2. 统一普通与流式话术接口：两者都必须通过独立的 `compliance-check`，流式场景先完成合规结果再向前端输出可见内容。
3. 为生成的话术保存输入快照、模型版本、合规结果和最终版本，以支持审计与问题追踪。
4. 补齐任务执行操作的鉴权、审计和幂等保护；任务状态变更触发客户时间线记录。
5. 将工作台由装饰性数据展示收敛为行动优先：今日待办、客户关键信号、话术、结果记录和下一步。

验收标准：

- 未通过合规检查的话术不会到达浏览器。
- 已完成、跳过、延期都有可追溯原因与操作者。
- 重复点击、页面刷新和网络重试不会制造重复执行记录。
- 当日任务与客户信息始终处于同一机构和同一咨询师授权范围内。

### P3：运营管理能力（F4-F8）

目标：管理员能通过真实数据管理 SOP、团队和效果，而不是仅查看静态看板。

工作项：

1. 实现 SOP 审核状态机及其权限和审计：`draft -> submitted -> approved/rejected`。
2. 建立团队与转移客户的约束：转移后任务、计划和可见性规则明确且可审计。
3. 用可解释的指标重做管理看板：任务完成率、超期率、录音处理成功率、标签人工修订率、转化漏斗。
4. 为管理操作提供筛选、分页、导出边界和异常状态展示。

验收标准：

- SOP 状态不可越级跳转，所有审批动作均有审计记录。
- 看板指标可追溯到具体业务数据，且机构之间完全隔离。

### P4：质量、可观测性与上线准备

目标：系统在真实试点机构中能被维护，而不是依赖人工排查和演示数据。

工作项：

1. 建立分层测试：租户授权、核心 API、Worker 幂等性、AI JSON 校验与合规拦截。
2. 结构化日志覆盖请求 ID、orgId、资源 ID、Job ID 和 AI 调用耗时；敏感内容脱敏。
3. 加入健康检查、队列积压/失败告警指标、错误边界和运行手册。
4. 整理环境变量校验、生产部署配置、数据库备份恢复和 OSS/Redis 故障预案。
5. 基于试点反馈建立提示词评估集：抽样人工标注标签准确度、策略可执行性和合规漏检率。

验收标准：

- CI 能执行 lint、类型检查和关键测试。
- 发生单个录音或单个模型调用失败时，不影响其他任务且可从日志定位。
- 新环境按文档可在不修改代码的条件下部署。

## 执行原则

1. 每个阶段先修数据模型和授权边界，再接 API，最后调整 UI。
2. 不为未验证需求预建复杂平台能力；F5-F8 只在 F1 与 F3 的实际使用数据稳定后推进。
3. 所有数据库变更采用 Prisma migration，禁止只依赖 `db push` 作为上线方案。
   当前初始化 migration 仅适用于新 PostgreSQL 环境；如需保留现有 SQLite 演示数据，先导出并经过字段映射校验后再导入，禁止直接覆盖生产库。
4. 每个工作项完成时提交最小可验证改动，并记录验证命令与已知限制。

## 本轮起始范围

本轮直接执行 P0：先审计和修复核心 API 的租户过滤/资源归属问题，再完成 PostgreSQL 迁移方案与测试基线。P1-P4 按上述验收标准依次推进，不在 P0 未通过前提前扩展 UI 功能。

## 已确认的 ASR 决策

生产环境选用腾讯云录音文件识别 `16k_zh_en_2.0`。选择依据是大陆可直接服务、异步长录音、说话人分离、词级时间戳、热词/定制能力及对复杂咨询室录音的适配。该决策不等同于宣称其在所有录音上准确率最高；上线前必须以脱敏的真实医美咨询录音完成抽样评测，并保留切换供应商的 `ASRProvider` 接口。

## 实施状态（2026-08-23）

已完成的代码工作：

1. PostgreSQL Prisma 基线、初始化 migration 和 Prisma CLI 固定入口。
2. 核心客户、录音、任务、标签、话术、SOP、推荐、日程接口的租户/归属边界修复。
3. 腾讯云 ASR 适配器、单 Worker 消费、任务重试传播、录音级计划幂等、标签多值与证据偏移。
4. 私有 OSS 对象键、ASR/播放短期签名 URL、录音 SSE 的事件 ID、心跳和重连边界。
5. 普通与 SSE 话术的独立合规拦截、生成审计记录、任务完成/跳过/延期的幂等状态处理。
6. SOP 审核状态机、客户转移时的待办同步、健康检查、运行手册、核心测试和 GitHub Actions CI。

必须在真实环境或由业务方完成的验收：

1. 启动 PostgreSQL、Redis、OSS 和 Worker，应用 `pnpm db:migrate` 后执行录音到任务的端到端测试。
2. 使用脱敏真实医美咨询录音评估腾讯云 ASR 的项目名、药械名、医生名与说话人分组效果，并维护热词版本。
3. 取得咨询师单独授权后，才可进行声纹角色认证灰度；不得采集客户声纹。
4. 在部署平台配置 GitHub Actions、数据库备份、告警接收方、腾讯云与 DeepSeek 密钥，并执行恢复演练。
5. 基于试点反馈补齐管理指标口径、提示词评估集和剩余非核心 API 的授权回归测试。
