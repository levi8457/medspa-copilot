# 咨询师移动 App PRD

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 医美 AI 智能管家 - 咨询师 App |
| 文档版本 | v1.0 |
| 日期 | 2026-08-29 |
| 产品定位 | 咨询师每天用来完成任务、在咨询现场获得实时转写与合规话术提醒的移动工作台 |
| 目标用户 | 医美机构咨询师；机构管理员仅负责 Web 端配置、审核与数据管理 |
| 依赖产品 | 现有 MedSpa Copilot Web 后台、PostgreSQL、Redis、OSS、DeepSeek、腾讯云 ASR |

## 1. 为什么要做

现有 Web 产品已经能在录音结束后完成“录音上传 -> 转写 -> 标签 -> 跟进计划 -> 任务 -> 话术”的闭环，但咨询师的高频工作发生在手机和咨询现场：

1. 上班先看今天要跟进谁、什么时候做、说什么。
2. 面谈时很难同时记客户原话、判断意向、查机构规范话术。
3. 面谈结束后再整理录音，容易遗漏客户顾虑与下一步动作。

App 的价值不是替咨询师说话，而是减少遗漏、帮助新人按机构标准服务、把有效经验沉淀为企业数字资产。咨询师仍然对沟通内容、医疗建议和最终操作负责。

## 2. 产品目标与非目标

### 2.1 目标

1. 让咨询师在 10 秒内知道今天最重要的任务和下一步动作。
2. 在取得客户同意后，提供低延迟的实时语音转文字，方便回看客户原话。
3. 结合当前客户、实时对话与机构知识资产，在合适时机给出简短、可执行、已合规审核的话术建议。
4. 将咨询过程沉淀为可追溯的录音、转写、要点、标签和后续任务，归属机构而非个人。
5. 弱网、来电、切换应用或识别失败时，确保录音和咨询过程不丢失。

### 2.2 v1 非目标

1. 不自动向客户发送微信、短信或拨打电话。
2. 不替代医生诊断、治疗方案、价格审批或医疗风险告知。
3. 不根据 ASR 的说话人编号自动断言“这是客户/这是咨询师”。
4. 不采集、注册或保留客户声纹；客户不同意录音时不得开启实时转写。
5. 不在 v1 中做全量 CRM 管理、管理员看板、SOP 编辑或复杂营销自动化，这些继续在 Web 端完成。

## 3. 核心使用场景

### 场景 A：早晨打开 App，处理今日任务

咨询师进入首页，看到“逾期、今日、即将到期”任务，优先处理高风险或高价值客户。点击任务后可查看客户摘要、上次沟通、推荐目标、已合规话术和快捷操作。

### 场景 B：接待到店客户，开启现场辅助

咨询师选择客户，展示录音知情同意提示；客户同意后开始录音和实时转写。页面持续显示临时转写文本、关键意向/顾虑信号和 1 至 3 条建议话术。咨询师可轻触查看、复制或标记“已使用”，但不会自动播放、自动发送或自动替人作答。

### 场景 C：客户提出异议

例如客户说“我担心效果不自然”或“价格有点高”。系统识别为候选信号后，优先在机构已审核的知识资产中检索对应话术；找不到时才调用 AI 生成建议，并在显示前经过医疗合规检查。建议必须附带适用场景和禁止承诺提示。

### 场景 D：咨询结束，完成闭环

咨询师结束录音，填写或确认“本次结果”和“下一步”。App 立即保存本地安全草稿并上传；后台继续做完整 ASR、标签提取和跟进策略生成。处理完成后，咨询师收到结果通知并可确认/修正标签与任务。

## 4. 用户与权限

| 角色 | App 权限 |
| --- | --- |
| 咨询师 | 仅查看本人名下客户、任务、录音、话术和本人产生的记录；可执行任务、开启已授权录音、查看建议、提交修正。 |
| 机构管理员 | 默认不使用咨询师 App；在 Web 端配置知识资产、审核 SOP/话术、查看团队数据、管理录音授权规则。 |
| 超级管理员 | 不默认访问机构原始录音或转写；仅在审计授权流程下处理平台级故障。 |

所有请求的机构和咨询师身份必须从登录令牌取得，App 不得传入或决定 `orgId`。咨询师更换机构、离职、禁用账号后，App 必须立刻失去数据访问权限并清理本地缓存。

## 5. 信息架构

底部使用四个主入口：

1. **今日**：任务摘要、待办列表、通知、快捷开始咨询。
2. **客户**：仅本人客户，搜索、客户摘要、历史记录与任务。
3. **现场**：选择客户后进入实时咨询辅助；无客户时只能进入演示模式，不能保存业务数据。
4. **我的**：个人资料、通知、录音授权说明、离线数据、隐私与退出登录。

“话术建议”不单独做成鼓励浏览的入口，而是嵌在任务详情、客户详情和现场辅助中；话术库浏览作为二级页面提供。

## 6. 功能需求

### F-A1：登录、设备与通知

**目标**：安全进入系统，并让咨询师不会错过重要任务。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| A1-01 | 支持账号密码登录；首次登录要求同意隐私政策和录音使用说明。 | P0 |
| A1-02 | 使用短期访问令牌和可撤销刷新令牌；不在 App、日志或崩溃报告中保存服务端密钥。 | P0 |
| A1-03 | 支持设备绑定与设备列表；管理员可在 Web 端让某台设备下线。 | P1 |
| A1-04 | 支持系统推送：新任务、任务到期、录音处理完成、管理员召回/禁用。 | P0 |
| A1-05 | 连续多次认证失败、令牌失效或账号被禁用时，清除本地业务缓存并回到登录页。 | P0 |

### F-A2：今日任务工作台

**目标**：让咨询师快速决定现在做什么。

1. 顶部显示：今日待办数、逾期数、已完成数、完成率；不展示团队排名或不必要的管理指标。
2. 默认排序：逾期 > 今日紧急 > 今日普通 > 明日预览；同级按计划时间和客户风险信号排序。
3. 每张任务卡展示：客户称呼、任务目标、计划时间、优先级、最近一次关键记录、推荐动作。
4. 支持操作：标记完成、跳过（必须选择/填写原因）、延期（必须选择新时间）、查看客户、生成/查看话术、发起现场咨询。
5. 任务完成后，写入客户时间线和审计日志；重复点击必须幂等，不能重复完成或产生多条事件。
6. 首屏任务数据可离线查看最近一次同步结果；离线时禁止伪造“已完成”，先进入待同步队列并明确标识。

**验收标准**：一名咨询师登录后只能看到自己且属于当前机构的任务；高优先级任务在 2 秒内显示；任务状态变更在网络恢复后只提交一次。

### F-A3：客户与咨询前准备

**目标**：进入面谈前用最少信息掌握重点。

1. 客户列表只显示本人客户；支持姓名、手机号后四位、项目标签搜索。
2. 客户摘要展示：当前阶段、核心需求、顾虑、已购项目、最近沟通、待办、风险提示。
3. 提供“咨询前速览”：最多 5 条关键事实和 3 条沟通提醒，避免把整份客户档案堆到现场页面。
4. 展示机构已审核、与该客户标签匹配的话术卡；每条卡标明适用场景、版本和更新日期。
5. 客户详情中的录音与全文转写默认不自动下载；需要时使用短期授权地址播放或查看。

### F-A4：实时咨询辅助（核心）

#### 6.4.1 开始前的同意与权限

1. 点击“开始现场咨询”后，先要求选择客户；不允许将真实业务录音保存为“无客户录音”。
2. 首次使用、每次机构规则变化或客户未留存有效授权时，展示明确提示：录音用途、AI 转写用途、保存期限、拒绝的替代服务方式。
3. 咨询师必须人工确认“客户已知情并同意”；系统记录同意版本、时间、操作者和客户关联。
4. 如果客户不同意：可继续查看客户摘要和手动记录，但“录音、实时转写、实时 AI 提醒”必须关闭。
5. App 需要系统麦克风权限；拒绝权限时给出设置指引，不允许后台偷偷录音。

#### 6.4.2 实时转写

1. App 采集单声道 16 kHz、16 bit 音频，按约 40 ms 音频片段连续发送；这符合腾讯云实时识别 WebSocket 的推荐实时传输方式。[腾讯云实时语音识别文档](https://cloud.tencent.com/document/product/1093/48982)
2. 客户端只与本项目后端建立安全连接；由后端生成短期会话凭证并代理/签发 ASR 会话，**绝不把腾讯云 SecretKey 放在 App 内**。
3. 实时转写分为“临时文本”和“确认文本”。临时文本可被后续结果改写，确认文本才可进入后续建议引擎与会话记录。
4. 屏幕显示滚动转写、录音时长、网络状态和“正在识别/重连中/仅本地录音中”状态。
5. 网络抖动时先本地加密缓存音频片段；恢复后按会话顺序补传。超过可恢复时限时，提示咨询师结束并上传完整录音走离线解析。
6. 实时 ASR 失败不得中断咨询。提供“继续本地录音”“重试实时转写”“结束咨询”三个明确选项。
7. 说话人分离只可显示“说话人 A/B/未知”，不得未经可靠确认标成客户或咨询师。实时说话人分离能力可作为后续增强项，且不能采集客户声纹。[腾讯云实时语音识别 V2 文档](https://cloud.tencent.com/document/product/1093/131127)

#### 6.4.3 实时最佳话术提醒

1. **触发条件**：确认文本命中机构定义的意向、顾虑、异议、项目、预算、预约、风险等信号；或咨询师手动点选“帮我找话术”。
2. **推荐优先级**：机构已审核话术库 > 当前客户已批准的 SOP 节点 > 基于客户标签的 AI 生成建议。AI 不得覆盖机构明确禁用的话术。
3. 每次只展示 1 至 3 条短建议，避免遮挡沟通和制造“念稿感”。默认静默显示，不播放语音、不弹窗打断、不震动打扰客户。
4. 话术卡包含：建议正文、适用原因、适用场景、来源（机构标准/AI 建议）、合规状态、复制/展开/不适用按钮。
5. AI 生成建议必须先通过现有 `compliance-check`，未通过则不显示；无法生成时回退到机构标准话术或显示“暂无安全建议”。
6. 不得生成医疗疗效保证、夸大宣传、替代医生诊断、诱导客户隐瞒禁忌症或绕过价格审批的话术。
7. 记录“建议已展示/已展开/已复制/标记不适用”，默认不记录“咨询师是否逐字说出”。这些行为数据用于改进资产排序，且必须可被机构配置关闭。

#### 6.4.4 会话结束与后处理

1. 点击结束时，App 显示：录音上传状态、会话摘要草稿、待确认事项、下一步动作。
2. App 将完整录音加密上传至私有 OSS，并创建 `AudioRecord`；长耗时的完整 ASR、标签、策略和任务生成继续由 BullMQ Worker 处理。
3. 实时文本只是辅助记录，后台完整转写结果是可追溯的正式版本；如两者不一致，应保留版本标记而非静默覆盖。
4. 咨询师可补充手动备注、标记关键原话、选择咨询结果；不得直接修改原始转写文本。
5. 完整处理完成后推送通知；咨询师可确认标签和后续任务，也可提出修正，修正必须保留原值、修改人和时间。

### F-A5：企业数字资产与话术检索

**目标**：让机构最佳实践在合适的时刻被找到，而不是成为无人阅读的资料库。

1. 资产类型：机构标准话术、项目资料、已批准 SOP 节点、合规禁用规则、常见异议处理、优秀案例摘要。
2. 所有资产必须有：机构归属、版本、状态、适用项目/场景/客户标签、创建人、审核人、生效时间与失效时间。
3. 仅 `approved` 状态的机构资产可用于实时推荐；草稿、已驳回、已下线资产绝不进入推荐。
4. 搜索支持关键词、场景、项目、客户阶段筛选；结果优先按当前客户相关性和机构配置排序，不以“全网热度”排序。
5. 咨询师可提交“个人收藏”和“建议新增话术”，但个人内容必须经过管理员审核后才可成为机构资产。

### F-A6：离线与弱网

| 场景 | 必须行为 |
| --- | --- |
| 无网络打开 App | 显示最近同步的今日任务和客户速览，并标出更新时间。 |
| 无网络开始咨询 | 若已有有效同意，可本地加密录音；不显示假实时转写和 AI 建议。 |
| 录音上传中断 | 自动断点续传；保留会话 ID、分片校验和上传进度。 |
| App 被系统杀死/来电打断 | 保存录音片段和会话草稿；回到 App 后提示继续、结束或丢弃。 |
| 本地存储不足 | 开始录音前预检；空间不足时禁止开始并给出释放空间指引。 |

本地缓存必须使用系统安全存储和应用级加密；成功上传并达到机构配置的确认条件后自动删除原始音频缓存。咨询师可在“我的”中查看待同步数量和手动清理非业务缓存，但无权删除已上传的机构原始记录。

## 7. 关键交互与界面原则

1. **今日页**：行动优先，不使用花哨大屏；首屏只展示最需要处理的 3 至 5 项。
2. **现场页**：大字、低干扰、单手可操作；转写为主，建议为辅。
3. **提醒方式**：默认静默卡片；只有任务逾期、上传失败、授权失效等业务风险才允许通知。
4. **可解释性**：每条推荐都要说明“为什么此刻推荐”，例如“客户刚表达对恢复期的顾虑”。
5. **可控性**：咨询师可以折叠建议、标记不相关；机构可以停用实时 AI 建议但保留转写。
6. **无障碍**：支持动态字体、深浅色对比、VoiceOver/TalkBack 基础标签；咨询现场不得依赖颜色作为唯一状态提示。

## 8. 数据、接口与系统设计约束

### 8.1 需要新增的核心对象

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| `ConsultationSession` | `orgId`、`customerId`、`consultantId`、状态、开始/结束时间、同意记录版本 | 一次现场咨询的主记录。 |
| `RecordingConsent` | 客户、会话、同意版本、同意时间、操作人、撤回时间 | 证明录音与 AI 处理的授权状态。 |
| `RealtimeTranscriptSegment` | 会话、序号、文本、临时/确认状态、时间范围、说话人分组 | 保存实时转写片段及版本。 |
| `RealtimeSuggestion` | 会话、触发信号、资产来源、内容快照、合规结果、展示/点击状态 | 保存建议的审计与效果数据。 |
| `DeviceSession` | 用户、设备标识、推送令牌、最后活跃时间、撤销状态 | 设备管理和推送。 |
| `OfflineUpload` | 会话、分片、校验值、状态、重试次数 | 断点续传和失败恢复。 |

所有业务对象必须含 `orgId` 并经过多租户中间件；涉及客户、咨询师、录音、话术与同意的读写均要写审计日志。

### 8.2 服务端接口能力

1. App 登录、刷新令牌、设备注册、注销与撤销。
2. 今日任务、本人客户、客户速览、任务状态变更和离线操作同步。
3. 创建/结束咨询会话、记录同意、音频分片上传、上传恢复与状态查询。
4. 实时会话鉴权：后端签发短期、单会话、单用户、可撤销的 ASR 访问凭证；客户端不能获得云厂商长期密钥。
5. 实时文本与建议下行通道：使用 WebSocket 或 SSE；客户端断线重连必须携带事件序号，避免重复显示。
6. 企业资产检索与话术建议；所有 AI 输出必须通过服务端合规过滤再返回。
7. 推送通知与已读回执。

### 8.3 ASR 方案边界

现有“录音文件识别 `16k_zh_en_2.0`”用于会后完整解析；实时能力必须新建独立的 `RealtimeASRProvider` 抽象，不能把长录音接口伪装成实时接口。腾讯云实时识别采用 WebSocket 并要求实时发送音频包；实时和录音文件识别应分别记录用量、失败率与延迟。[腾讯云 API 概览](https://cloud.tencent.com/document/product/1093/134682)

实时模型、并发和价格在上线前必须用脱敏的真实咨询录音与现场环境 POC 验证。v1 的验收目标是“可用的实时辅助”，不是承诺逐字无误或自动识别人员身份。

## 9. 隐私、合规与安全要求

1. 录音前知情同意为 P0 阻断条件；没有同意不得开启录音和实时 AI 分析。
2. 明确告知：录音目的、AI 转写/建议用途、存储位置与期限、查看对象、撤回方式。
3. 客户撤回授权后，立即阻止新的录音/分析；历史数据的处置按机构法务政策执行并可审计。
4. 原始录音、转写和建议内容均属于敏感业务数据：传输加密、私有 OSS、短期签名访问、最小权限、服务端密钥管理。
5. 不记录完整转写、音频链接、访问令牌或云密钥到客户端日志、分析 SDK 或崩溃报告。
6. 所有话术建议必须走医疗合规检查；系统显示“仅供咨询辅助，不构成医疗建议”。
7. 管理员可配置允许实时辅助的机构、项目、门店和咨询室；默认关闭对未完成培训人员的实时 AI 建议。

## 10. 非功能需求与验收指标

| 类别 | v1 要求 |
| --- | --- |
| 启动与任务 | 已登录状态下，今日页 2 秒内显示缓存内容，5 秒内完成在线刷新。 |
| 实时转写 | 网络正常时，确认文本端到端 P95 延迟不高于 2 秒；临时文本允许后续修订。 |
| 话术提醒 | 从确认文本触发到展示 P95 不高于 3 秒；无可用建议时不阻塞转写。 |
| 可靠性 | 会话中断后，已写入本地的音频片段不丢失；上传成功率目标不低于 99%。 |
| 安全 | 不允许越机构、越咨询师读取；所有敏感操作可审计。 |
| 可用性 | ASR/AI 不可用时，任务、客户速览和本地录音仍可工作。 |
| 兼容性 | Android 优先支持主流设备；iOS 与 Android 均需支持当前主流系统版本，具体最低版本在技术方案阶段确定。 |

## 11. 埋点与成功指标

| 指标 | 定义 | v1 目标 |
| --- | --- | --- |
| 日任务执行率 | 当天完成任务 / 当天应完成任务 | 提升 15% 以上 |
| 任务逾期率 | 逾期任务 / 应完成任务 | 降低 20% 以上 |
| 现场辅助渗透率 | 至少开启一次现场辅助的活跃咨询师 / 活跃咨询师 | 试点期 >= 50% |
| 建议采纳率 | 复制或展开建议次数 / 建议展示次数 | 只做观察，不设强制 KPI |
| 实时会话成功率 | 正常结束并产出可用记录的会话 / 发起会话 | >= 95% |
| 合规拦截率 | 被合规拒绝的 AI 建议 / AI 尝试生成建议 | 监控异常波动，不以低为唯一目标 |

禁止用“咨询师照读率”或“客户成交率”直接评价单条实时话术，避免诱导过度营销和不当医疗宣传。

## 12. 版本范围与实施顺序

### P0：试点可用版本

1. 登录、设备管理、今日任务、本人客户速览、任务状态变更。
2. 录音知情同意、选择客户、前台/弱网本地录音、断点上传。
3. 实时转写（无自动角色判断）、实时文本展示和完整录音后处理衔接。
4. 基于“机构已审核话术库”的静默推荐；保留人工搜索和复制。
5. 推送、审计、基本离线缓存、健康监控和试点数据看板。

### P1：提升建议质量

1. 基于客户标签、SOP 节点和实时信号的个性化建议。
2. 经过合规检查的 AI 生成建议与建议反馈闭环。
3. 会话总结、客户标签确认、下一步任务确认。
4. 机构资产版本、推荐效果和咨询师反馈管理。

### P2：验证后再做

1. 实时说话人分组辅助、质检摘要、优秀案例挖掘。
2. 与排班、电话、企业微信等外部系统的受控集成。
3. 管理员对实时辅助的精细规则配置与 A/B 测试。

## 13. 上线前必须完成的决策

1. **形态选择**：本 PRD 建议做 Android 优先的原生能力 App，并同步规划 iOS；实时音频、后台运行和断点续传不应只依赖移动网页。具体跨端框架在技术方案评审后决定，不能直接复用 Next.js Web 页面冒充 App。
2. **试点范围**：明确 1 至 2 家机构、10 至 30 名咨询师、允许使用的项目和咨询室。
3. **法务授权文本**：由机构法务确认录音、AI 处理、保存期限和撤回流程，产品不能自行编造合法授权。
4. **知识资产准入**：明确谁能发布、谁审核、多久复审、下线后如何处理已推荐历史。
5. **实时 ASR POC**：用脱敏现场录音评估延迟、项目名准确率、网络抖动恢复、并发与费用；达不到阈值时仅上线“本地录音 + 会后解析”。
6. **运营边界**：明确是否允许在咨询现场展示价格、促销、案例内容，以及哪些内容必须由医生/管理员确认。

## 14. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 录音授权不充分 | 以版本化同意记录作为强制前置条件，先做法务评审再试点。 |
| 弱网造成会话丢失 | 本地加密缓存、分片续传、会后完整解析兜底。 |
| ASR 误识别导致错误提醒 | 建议只基于确认文本；展示“参考建议”和来源，不自动执行。 |
| AI 话术不合规 | 机构资产优先、服务端强制合规检查、失败时不展示 AI 文本。 |
| 建议太多干扰沟通 | 单次最多 3 条、默认静默、允许一键关闭。 |
| 咨询师担心被监控 | 明确记录什么/不记录什么，试点前培训，不把采纳率作为个人考核。 |
| 云端成本失控 | 分开监控实时 ASR、文件 ASR、LLM 调用；配置会话时长和并发上限。 |

## 15. 验收场景

1. 咨询师 A 无法通过搜索、接口参数或离线缓存看到咨询师 B 或其他机构的客户/任务。
2. 客户未同意录音时，现场页不能开始录音、实时转写或 AI 提醒，但可记录手动备注。
3. 网络正常时，开始会话后能持续看到临时和确认文本；建议不会在未通过合规检查时出现。
4. 断网后继续咨询，恢复网络后完整音频只上传一次；不会创建重复 `AudioRecord`、标签或任务。
5. 客户表达价格/效果/恢复期顾虑时，若机构已有审核话术，优先显示该资产并标明来源。
6. ASR 或 AI 服务故障时，咨询师可完成本地录音和结束会话，系统不假装“已识别成功”。
7. 会话结束后，后台完整处理结果可回到同一客户档案；咨询师能确认/修正建议标签，且修正有审计记录。
